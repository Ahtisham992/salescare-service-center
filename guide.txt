## 🚀 Setup Instructions

### 1. Backend Setup

```bash
# Navigate to backend
cd backend

# Install dependencies
npm init -y
npm install express pg dotenv bcryptjs jsonwebtoken cors helmet morgan
npm install --save-dev nodemon

# Development dependencies
npm install joi express-validator pdfkit
```

### 2. Frontend Setup

```bash
# Navigate to frontend
cd frontend

# Create React app
npx create-react-app .

# Install dependencies
npm install react-router-dom axios
npm install @tanstack/react-query
npm install react-hook-form
npm install tailwindcss postcss autoprefixer
npm install lucide-react
npm install date-fns
npm install react-hot-toast

# Initialize Tailwind
npx tailwindcss init -p
```

### 3. Environment Variables

Create `.env` in backend:

```env
# Server
PORT=5000
NODE_ENV=development

# Database
DB_HOST=localhost
DB_PORT=5432
DB_NAME=salescare_db
DB_USER=postgres
DB_PASSWORD=your_password

# JWT
JWT_SECRET=your_super_secret_key_change_in_production
JWT_EXPIRE=7d

# App
COMPANY_NAME=SalesCare Service Center
DEFAULT_AREA=Rawalpindi, PEL Service Center
```

## 📋 Key API Endpoints

### Authentication
- `POST /api/auth/login` - User login
- `POST /api/auth/logout` - User logout
- `GET /api/auth/me` - Get current user

### Complaints
- `GET /api/complaints` - List all complaints
- `POST /api/complaints` - Create complaint
- `GET /api/complaints/:id` - Get complaint details
- `PUT /api/complaints/:id` - Update complaint
- `PATCH /api/complaints/:id/assign` - Assign technician
- `PATCH /api/complaints/:id/status` - Update status

### Invoices
- `GET /api/invoices` - List invoices
- `POST /api/invoices/counter-sale` - Create counter sale invoice
- `POST /api/invoices/complaint` - Create complaint invoice
- `GET /api/invoices/:id/pdf` - Generate invoice PDF
- `GET /api/invoices/:id` - Get invoice details

### Inventory
- `GET /api/inventory/stock` - Get stock in hand
- `GET /api/inventory/transactions` - Transaction history
- `POST /api/purchase-orders` - Create PO
- `POST /api/goods-receipts` - Create GR
- `POST /api/delivery-orders` - Create DO

### Material Requisitions
- `POST /api/requisitions/mrqs` - Create MRQS
- `POST /api/requisitions/mrts` - Create MRTS
- `GET /api/requisitions/:id` - Get requisition details
- `PATCH /api/requisitions/:id/approve` - Approve requisition
- `PATCH /api/requisitions/:id/issue` - Issue materials

### Reports
- `GET /api/reports/complaints-summary` - Complaint summary
- `GET /api/reports/revenue` - Revenue report
- `GET /api/reports/inventory-valuation` - Inventory value
- `GET /api/reports/technician-performance` - Technician stats

## 🔄 Business Logic Flow

### 1. **Complaint to Invoice Flow**
```
Customer → Complaint Created → Technician Assigned → 
MRQS Generated → Parts Issued → Service Completed → 
Invoice Generated (Service Charges + Parts)
```

### 2. **Counter Sale Flow**
```
Customer Walk-in → Delivery Order Created → 
Inventory Deducted → Invoice Generated
```

### 3. **Inventory Flow**
```
Purchase Order → Goods Receipt → Inventory Updated →
MRQS/DO Issue → Inventory Deducted → Transaction Logged
```

## 💡 Important Implementation Notes

### Auto-Number Generation
All document numbers (Invoice#, Complaint#, DO#, MRQS#) should be auto-generated with format:
- Format: `PREFIX-YYYY-NNNNNN`
- Example: `RWP-2024-002878`, `MRQS-2024-000123`

### Inventory Management
- Use **transactions** for all inventory movements
- Log every change in `inventory_transactions`
- Implement **optimistic locking** to prevent race conditions
- Calculate stock in real-time from transactions

### Invoice Calculations
- Service charges from tariff table
- Parts amount from MRQS
- GST/FST calculations
- Discount & waive-off logic
- Round to 2 decimal places

### Warranty Logic
- Check warranty status based on purchase date
- Different pricing for UW/OPB/Con W/Con P
- Auto-calculate warranty expiry

## 🔐 Security Considerations

1. **Authentication**: JWT tokens with expiry
2. **Authorization**: Role-based access control
3. **Input Validation**: Sanitize all inputs
4. **SQL Injection**: Use parameterized queries
5. **Password**: Hash with bcrypt (salt rounds: 10)
6. **CORS**: Restrict to frontend domain only
7. **Rate Limiting**: Prevent API abuse
8. **Audit Trail**: Log all critical operations
